## Подход к процессу

Команда небольшая, поэтому полный Scrum не используется. Выбран облегчённый Kanban:

- доска с колонками «Бэклог», «В работе», «На ревью», «Готово»;
- ограничение незавершённой работы: не больше двух задач в колонке «В работе» на человека;
- недельное планирование из бэклога, собранного по [карте историй](user-story-map.md);
- задачи режем по сценариям (вертикальные срезы): после каждого среза пользователь может выполнить осмысленное действие целиком.

## Определение готовности

Задачу можно брать в работу, если:

- [ ] Есть критерии приёмки в формате «Дано — Когда — Тогда»
- [ ] Указано, какой истории из карты она соответствует
- [ ] Понятно, каким изменением в интерфейсе или API она проявится
- [ ] Нет незакрытых вопросов к формулировке
- [ ] Задача помещается в одну неделю; если нет — разбита

## Определение завершённости

Задача считается сделанной, если:

- [ ] Код внедрён в основную ветку через запрос на слияние
- [ ] Запрос прошёл ревью второго участника с содержательными комментариями
- [ ] Конвейер проверок зелёный
- [ ] Написаны тесты на критерии приёмки, они проходят
- [ ] Документация обновлена: README или соответствующий файл в docs/
- [ ] Добавлена запись в docs/CHANGELOG.md
- [ ] Изменение проверено на чистом окружении (не только «у меня работает»)
- [ ] Для брони и оплаты: проверен случай конфликта (две попытки занять один слот)

Последний пункт специфичен для настоящего проекта: двойная бронь — главная проблема из числа решаемых проектом.

## Ритм команды

| Событие | Когда | Длительность | Формат |
| --- | --- | --- | --- |
| Синхронизация | Пн, Чт, 19:00 | 15 мин | Что сделал, что буду, что мешает |
| Планирование недели | Пн, после синхронизации | 30 мин | Разбор задач на неделю из бэклога |
| Ретроспектива | Каждую вторую Пт | 30 мин | Что работало, что мешало, одно изменение на две недели |

## Как принимаем решения

- Решения по продукту и архитектуре обсуждаем и фиксируем письменно
- При разногласии: если не договорились за 15 минут, выносим преподавателю
- Любое решение, которое трудно откатить, записывается
- Технический долг записывается в бэклог и имеет срок возврата
